# [Cowork 프롬프트] 민사소송(법원실무제요) 직원용 admin HTML 생성

> 사용법: 아래 전체를 Cowork에 그대로 붙여넣는다. 단, 맨 위 **[연결 폴더 확인]** 항목은
> 실제 작업 폴더가 연결되어 있는지 먼저 확인한 뒤 진행한다.

---

## 0. 연결 폴더 확인 (생성 전 필수)

작업을 시작하기 전에, 연결된 폴더에서 다음 3종이 같은 상위 폴더 안에 함께 있는지 확인하라.

- `민사소송(법원실무제요)` 계열 **md 폴더** (원본 텍스트)
- `민사소송(법원실무제요)` 계열 **pdf 폴더**
- `민사소송(법원실무제요)` 계열 **기존 html 폴더** (= 이미 생성된 **고객용** HTML)

확인 후, 이 상위 폴더 안에 새 폴더 **`민사소송(법원실무제요)admin html`** 을 만들고 그 안에 결과물을 생성한다.

---

## 1. 역할과 목적

너는 법무사 사무소의 **내부 직원용(admin) 실무 지원 페이지**를 만든다.
이 페이지는 대외 배포용이 아니라, 사무소 직원이 해당 사건을 정확하고 효율적으로 처리하고
**법무사의 실무 노하우와 주의점을 사무소 자산으로 축적·전수**하기 위한 내부 업무 도구다.

> 이 페이지의 진짜 가치는 교재 요약이 아니라, **"실무에서 사고가 나는 지점과 그것을 피하는 법무사의 노하우"** 다.
> 교재(법원실무제요)에 있는 일반론은 토대일 뿐이고, 그 위에 **현장에서 축적된 판단·요령·함정 회피**를 얹는 것이 목적이다.

### 고객용과의 근본적 차이 — 절대 혼동하지 말 것

| 구분 | 고객용 (기존 html) | 직원용 admin (이번 작업) |
|------|--------------------|--------------------------|
| 목적 | 정보 홍보, 상담 유도 | 실무 정확성, 업무 효율, **노하우 축적·전수** |
| 독자 | 비전문가 의뢰인 | 법무사·사무직원 |
| 언어 | 쉬운 일반어, 용어 최소화 | 정확한 법률 용어, 조문·산식 그대로 |
| 비용 | **금액 표시 금지** (종류·횟수만) | **금액·산식 표시 허용** (실무 도구이므로) |
| 분위기 | 신뢰감, 안심, CTA 유도 | 정보 밀도, 체크리스트, 검증 상태, 실무 TIP |
| 제외 요소 | — | 상담 CTA·면책 문구·고객 안심 문구 일체 **제외** |
| 추가 요소 | — | "내부용 · 대외 배포 금지" 표시 상단 고정 + 노하우/현장메모 |

> 핵심 지침: **직원이 이 페이지 하나만 보고도 사건의 핵심쟁점을 파악하고, 절차를 빠짐없이 밟고,
> 첨부서류를 법령 근거와 함께 챙기고, 비용·소가를 산정하고, 법무사가 겪은 함정을 미리 피할 수 있어야 한다.**

## 2. 입력 자료 처리

1. **md 폴더의 민사소송(법원실무제요) 원본**을 읽어 실체·절차 내용을 파악한다.
2. **기존 고객용 html**을 열어 **어떤 주제(페이지)들이 다뤄졌는지** 목록을 추출한다.
3. 직원용 admin은 **고객용과 동일한 주제 단위로 1:1 대응하여, 주제마다 개별 HTML 파일을 각각 생성**한다.
   - 고객용 페이지가 N개면 직원용도 **N개의 개별 파일**을 만든다. 통합 1개 파일로 합치지 않는다.
   - 고객용 1개 파일 ↔ 직원용 1개 파일이 정확히 대응되어야 한다.
4. 주제는 그대로 유지하되, **서술 관점만 직원 실무용으로 전환**한다.

## 3. 직원용 페이지 구성 — 고정 7섹션 구조

각 주제(페이지)는 아래 순서를 반드시 지킨다. 고객용의 유형1/유형2 구조는 사용하지 않는다.

### 상단 고정 — 업무 요약 헤더 (배지 형태)
한눈에 보이도록 배지/표로 요약:
- 사건유형 · 관할(법원) · 근거 법령 · 당사자 · 표준 처리기간(개략)
- 우측 상단에 **`🔒 내부용 · 대외 배포 금지`** 표시

### 상단 고정 — ⚠️ 법무사 업무범위·수임 판단 박스 (가장 먼저 봐야 할 것)
이 사건을 법무사가 어디까지 처리할 수 있는지, 받아도 되는지를 먼저 판단하게 한다.
- **업무범위 한계**: 법무사는 소송대리권이 없다. **서류 작성·제출 대행** 범위만 가능하며, 법정 대리·교섭은 불가.
  변론·법률상담 영역을 넘으면 변호사법 위반 소지 → 그 경계를 명시한다.
- **수임 판단 포인트**: 소멸시효·제소기간 도과 여부 먼저 확인, 실익(승소·회수 가능성) 판단,
  위임 범위(어디까지 대행하는지) 명확화, 이해상충 확인.
- 이 사건 유형에서 **"받지 말아야 하거나 변호사 연계가 필요한 신호"** 를 체크리스트로.

### 섹션 1 — 핵심쟁점 (실체·절차)
이 업무에서 **반드시 짚어야 할 법적 쟁점**을 실체/절차로 나눠 정리한다.
- **실체적 쟁점**: 권리·법률관계의 성립요건, 효과, 다툼의 핵심
- **절차적 쟁점**: 관할, 당사자적격, 소송요건, 제소기간 등
- "이것을 놓치면 각하·기각·보정 대상이 된다"는 **결정적 체크포인트**를 강조 박스로.

### 섹션 2 — 업무 절차 흐름
접수부터 종결까지 단계별 흐름. 각 단계에 **법무사 작업 내용 + 주의점 + 💡실무 TIP**을 병기한다.
예시 골격(주제에 맞게 조정):
사실관계·증거 검토 → 관할·당사자 확정 → 서류 작성 → (전자소송) 제출 → 보정 대응 → 송달 → 변론/결정 → 종결·후속처리
- 전자소송 단계는 사무소 ecfs 작업 흐름과 연결되도록 작성한다.
- 단계마다 "여기서 자주 막힌다 / 여기서 시간이 걸린다"는 현장 정보를 TIP으로 덧붙인다.

### 섹션 3 — 첨부서류 (법령 근거 정리)
**표 형식 필수.** 컬럼:

| 서류명 | 필수/선택 | 법령·예규 근거 | 발급처 | 유효기간 | 실무 비고(TIP) |
|--------|-----------|----------------|--------|----------|----------------|

- 근거는 조문·예규까지 명시하고, **섹션 5의 법령 태그와 연결**한다.
- "실무 비고" 칸에는 발급 소요시간, 자주 누락되는 서류, 원본/사본 구분, 유효기간 도과 주의 등 현장 요령을 적는다.
- 등기·집행 등 첨부서류는 최신 개정 반영 여부를 ⚠️로 표시.

### 섹션 4 — 비용·소가 산정
직원용이므로 **금액·산식 표시 허용.**
- **소가 산정**: 산정 기준·방법(주제별), 비재산권상 사건 여부 구분
- **인지액·송달료**: 산식 또는 기준 제시
- 사무소의 **비용계산 프로그램 / 소가산정 프로그램이 있으면 해당 페이지로 링크**(상대경로) 삽입.
  링크가 없으면 "→ 비용계산 프로그램 연동 예정" 자리표시자(placeholder)를 둔다.
- 💡TIP: 의뢰인에게 비용을 미리 고지할 때의 표현·범위, 추가비용 발생 지점을 적는다.

### 섹션 5 — 법령·판례 검증
관련 법령·판례를 **공식 사이트 링크 태그**로 정리하고 **검증 상태**를 표시한다.
- 각 항목 끝에 ✅(원문 확인 완료) / ⚠️(재확인 필요) 배지.
- 태그 형식·링크 규칙은 아래 **[법령·판례 작성·검증 규칙]** 을 그대로 따른다.

### 섹션 6 — 법무사 실무 노하우 ★ (이 페이지의 핵심)
교재에 없는, **현장에서 축적된 처리 요령**을 모은다. 아래 소항목으로 나눠 작성한다.
- **수임·상담 단계 노하우**: 의뢰인에게 반드시 먼저 물어야 할 것, 말만 믿지 말고 직접 확인할 것
  (등기부·증거·시효 등), 사건의 실익을 빠르게 판단하는 기준.
- **서류 작성 노하우**: 청구취지·신청취지 특정 요령, 당사자 표시 정확성(법인은 등기부상 명칭·대표자),
  관할·송달주소 확인, 자주 틀리는 기재 포인트.
- **제출·송달 노하우**: 전자소송 제출 타이밍, 인지·송달료 납부 순서, 보정명령 예방·신속 대응,
  송달불능 시 처리(보정·공시송달 등) 요령.
- **의뢰인 관리 노하우**: 진행상황 보고 시점, 기간 관리(다이어리·알림), 기대치 조정, 분쟁 예방.
- 각 항목은 **💡 형태의 실무 TIP**으로 작성하고, 교재 출처가 없는 현장 지식은
  `📝 [직접 추가] 현장 메모` 자리표시자를 두어 법무사가 직접 채우도록 한다.

### 섹션 7 — 주의사항 & 사고·실수 사례
"이렇게 하면 사고 난다"를 구체적으로 모은다.
- ⚡ **기간 도과 위험**: 넘기면 권리·이익을 잃는 기간을 최상단에.
- **흔한 실수 / 보정명령 단골 사유 / 각하·기각으로 이어지는 패턴**을 사례식으로.
- **변호사법 경계 사고**: 대리·교섭으로 오해받을 행위, 피해야 할 표현.
- **의뢰인 안내·확인이 필요한 항목**: 직원이 의뢰인에게 반드시 확인해야 할 것.
- 가능하면 "사고 → 원인 → 예방책" 3단 구조로 적는다.

## 4. 디자인 시스템 (admin 변형)

기본 색·폰트는 사무소 표준을 따르되, **내부 도구다운 밀도·기능성**을 우선한다.

```
주색:         네이비   #1a2e4a
포인트:       골드     #c8a96e
배경:         아이보리 #faf8f5
업무범위 경고: 배경 #fff3e8 / 테두리 #c05000 (상단, 가장 눈에 띄게)
핵심쟁점:     배경 #f4f7fb / 테두리 #2d4a7a
절차 흐름:    배경 #eef2f8 / 테두리 #2d4a7a
첨부서류 표:  헤더 네이비 배경 + 흰 글자, 줄무늬 행
실무 TIP 박스: 배경 #f0f8f0 / 테두리 #1a5c2e / 💡 아이콘
현장 메모:    배경 #fffdf5 / 점선 테두리 #c8a96e / 📝 아이콘 (입력 자리)
검증 ✅:      녹색 #1a5c2e 계열 배지
검증 ⚠️:      주황 #c05000 계열 배지
함정/사고:    배경 #fff3e8 / 테두리 #c05000
내부용 표시:  배경 #2d2d2d / 흰 글자 (상단 고정 바)
제목 폰트:    Noto Serif KR
본문 폰트:    Noto Sans KR
```

- 표·체크리스트·배지·TIP 박스를 적극 사용하고, 여백보다 **정보 밀도**를 우선한다.
- 상담 CTA 박스, 고객 안심 문구, 면책 문구는 **넣지 않는다.**
- 대신 페이지 최하단에 **내부 메모/개정 이력 영역**(작성일·근거 기준일·최종 검토자)을 둔다.

## 5. 법령·판례 작성·검증 규칙 (필수)

### 법령 태그 (law.go.kr · docType=JO 방식)
```html
<div class="ref-tags">
  <a href="https://www.law.go.kr/lsInfoP.do?docType=JO&lsiSeq={lsiSeq}&joNo={joNo}" target="_blank" class="tag-law">
    📋 민사소송법 제○○조
  </a>
</div>
```
- `joNo`: 조문번호를 **6자리 + 00**. 예) 제34조 → `003400`, 제248조 → `024800`
- 주요 lsiSeq: 민사소송법 `252393` · 민법 `122983` · 부동산등기법 `59791` · 가사소송법 `103961`
- 목록에 없는 법령은 law.go.kr에서 검색해 **실제 lsiSeq를 확인 후** 기재(추정 금지).

### 판례 태그 (glaw.scourt.go.kr)
```html
<div class="ref-tags">
  <a href="https://glaw.scourt.go.kr/wsjo/panre/sjo060.do?q={사건번호}" target="_blank" class="tag-case">
    ⚖️ 대법원 ○○○○다○○○○○
  </a>
</div>
```
- 사건번호만 기재(선고일자 표시 안 함).

### ⚠️ AI 생성 금지 — 가장 중요
- **판례 사건번호를 임의로 생성하지 않는다.** md·교재·자료에 있는 번호만 사용한다.
- 자료에 사건번호가 없으면 판례 태그를 만들지 말고, 본문에 법리 방향만 서술한다.
- 가상의 법령 URL·조문번호를 만들지 않는다.
- **노하우·주의사항도 마찬가지로, 출처 없는 단정적 사실(금액·기간·예규 번호 등)은 지어내지 않는다.**
  현장 지식이지만 확정 표현이 어려운 부분은 `📝 [직접 추가] 현장 메모`로 비워 두고 법무사가 채우게 한다.
- 직원용에서는 각 법령·판례 옆에 ✅/⚠️ 검증 배지를 달아, **원문 대조 완료 여부**를 명시한다.

## 6. 출력 규칙

- 생성 위치: pdf·md·기존 html 폴더와 **동일한 상위 폴더** 안.
- 새 폴더명: **`민사소송(법원실무제요)admin html`**
- **주제별로 개별 HTML 파일을 각각 생성한다.** 고객용 파일명에 `_admin` 접미사를 붙여 1:1 대응을 명확히 한다.
  예) 고객용 `소액사건.html` → 직원용 `소액사건_admin.html`
- 각 HTML은 단일 파일(인라인 CSS)로 생성하여 폴더 내에서 바로 열리게 한다.
- 폴더에 `index_admin.html`(전체 주제 목차 + 각 개별 파일로 가는 링크 모음)을 **반드시 함께** 만든다.

## 7. 생성 후 자체 점검 체크리스트

- [ ] 상단 업무요약 헤더 + `🔒 내부용` 표시 + **법무사 업무범위·수임 판단 박스**가 모두 있는가
- [ ] 7섹션 구조가 순서대로 들어갔는가 (특히 섹션 6 노하우 · 섹션 7 사고사례)
- [ ] 고객용 페이지마다 직원용 **개별 파일이 1:1로 생성**되었는가 (통합하지 않았고 누락 주제 없는가)
- [ ] 각 파일명이 고객용 + `_admin` 규칙을 따르는가
- [ ] `index_admin.html` 목차에 모든 개별 파일 링크가 들어갔는가
- [ ] 첨부서류 표에 법령·예규 근거 + 실무 비고(TIP)가 채워졌는가
- [ ] 절차·노하우 섹션에 💡실무 TIP과 📝현장 메모 자리가 있는가
- [ ] 변호사법 경계(업무범위 한계)가 명확히 서술되었는가
- [ ] 모든 법령 링크가 docType=JO 형식이고 lsiSeq·joNo가 정확한가
- [ ] 판례 사건번호가 전부 자료 출처가 있는 실제 번호인가 (생성된 번호 없음)
- [ ] 각 법령·판례에 ✅/⚠️ 검증 배지가 달렸는가
- [ ] 상담 CTA·면책 문구가 **들어가지 않았는가** (직원용에는 불필요)
- [ ] 비용·소가 섹션에 계산 프로그램 링크 또는 placeholder가 있는가
- [ ] 최하단에 작성일·근거 기준일·검토자 메모 영역이 있는가

# Phase 5 파일럿 런북 — 새 더미 재검증 & 실사건 시범 운영

이 문서는 sop.md의 기술 설명과 별개로, **직원이 직접 손으로 따라 하는 체크리스트**다. Claude 없이도 이 문서만 보고 진행할 수 있도록 작성했다.

---

## 0. 진행 순서 요약

1. 새 더미 사건으로 STEP1~10 재검증 (아직 안 끝남 — 최우선)
2. 통과하면 실제 사건 1~2건 파일럿 (직원 입회)
3. 문제없으면 admin 페이지 기본 실행 경로로 전환

---

## 1. 새 더미 사건 재검증 (최우선 — 아직 미완료)

**왜 다시 해야 하나**: 2026-07-21 라이브 테스트에서 같은 더미 사건에 여러 번 반복 등록을 시도하다 화면이 멈추는 문제(유령 모달)가 발생했다. 코드는 고쳤지만, 이게 "반복 시도로 오염된 사건이라 생긴 문제"였는지 "새 사건에서도 똑같이 생기는 진짜 버그"였는지 아직 확정 못했다. **완전히 새 더미 사건**으로 한 번 더 확인해야 한다.

### 준비물
- 사무실 PC, 인증서
- `ecfs-automation` 폴더의 `3_start_server.bat`, `2_start_chrome_debug.bat`

### 절차

1. `2_start_chrome_debug.bat` 실행 → 새로 뜬 Chrome 창에서 인증서로 로그인.
2. **반드시 새 사건으로** "서류제출 → 소장 → 작성하기" 진입 → "전자소송 동의" 체크박스가 보이는 화면까지 이동. (기존에 만들어 둔 더미 "대여금" 사건은 재사용하지 말 것 — 오염 의심.)
3. `3_start_server.bat` 실행 (서버 로그 창이 뜨고 "ECFS 자동화 서버 실행 중" 메시지 확인).
4. `test_trigger.html`을 아무 브라우저에서나 열고 "7) 전체 흐름 (run-full)" 섹션의 예시 payload를 그대로 사용해 [전체 흐름 실행] 클릭. (payload 안의 사건명·소가는 원하는 값으로 바꿔도 되지만, 처음엔 예시 그대로가 안전하다.)
5. 화면 하단 "진행상황" 영역이 3초마다 갱신된다. STEP1 → STEP2 → ... → STEP10까지 순서대로 `done`이 뜨는지 지켜본다.
6. **만약 또 멈추면**: 서버 로그 창에 `_modal`이라는 단어가 있는 에러가 보이는지 확인하고, 그 시점에 디버그 Chrome 화면을 직접 봐서 정말 아무 팝업도 안 보이는지 확인한다. 안 보이는데도 멈추면 이번엔 진짜 코드 문제이니 캡처해서 다음 세션에서 Claude에게 보여줄 것.
7. STEP10까지 정상 도달하면: 그 더미 사건은 **임시저장 상태**로 남아있다. 화면에서 직접 열어 각 항목(당사자·청구취지·청구원인·소명서류)이 실제로 잘 채워졌는지 눈으로 확인한다.
8. 확인이 끝나면 그 더미 사건은 삭제한다 ('나의전자소송 → 작성중서류'에서 삭제).

### 이 단계에서 특히 봐야 할 것 (아직 한 번도 실측 못한 부분)
- 피고(자연인) 정보가 정확히 들어갔는지 (`ecfs_party_input.js`의 `submitDefendant`는 아직 실측 미검증 상태였음)
- 소명서류 업로드 후 그리드에서 서증번호("갑 제1호증" 등)·서류명이 올바르게 표시되는지 (그리드 셀 쓰기도 미검증 상태였음)

## 2. 실사건 파일럿 (1단계 통과 후 진행)

### 사건 선정 기준
- 비교적 단순한 사건 (당사자 1:1, 금전청구, 소명서류 1~2개) 로 시작
- 급하지 않은 사건 (임시저장까지만 자동화되므로 최종 검토·제출은 어차피 법무사가 직접 해야 함)

### 절차

1. 위 1단계와 같은 방식으로 서버·디버그 Chrome 준비, 실제 사건 화면으로 "전자소송 동의"까지 진입.
2. `test_trigger.html`의 payload를 **그 사건의 실제 정보**로 채워서 실행. (주민번호·주소 등 실제 개인정보가 들어가므로 화면 공유 시 주의.)
3. 직원이 화면 옆에서 지켜보며, 각 STEP이 실제로 올바른 값을 입력하는지 확인. 이상하면 즉시 서버 창에서 Ctrl+C로 중단 가능.
4. STEP10(최종 임시저장)까지 도달하면, **절대 그대로 제출하지 말고** 법무사가 처음부터 끝까지 화면을 다시 검토한 뒤 직접 "작성완료 → 제출" 버튼을 눌러 제출한다.
5. 자동화가 채운 내용과 원래 손으로 입력했을 내용을 비교해 차이가 없는지 기록해 둔다.

### 최소 2건 반복
서로 다른 사건 유형(예: 대여금 1건 + 매매대금 1건)으로 각각 1회 이상 진행 권장.

## 3. 문제 발생 시 대응

| 증상 | 대응 |
|---|---|
| 서버가 `needsManualReview: true`를 반환 | 그 사건은 자동화가 실패한 것 — 디버그 Chrome 화면을 직접 열어 어디서 멈췄는지 확인 후 이어서 손으로 완료 |
| 화면이 멈추고 아무 반응 없음 | 서버 로그 창(`3_start_server.bat` 콘솔)에서 에러 메시지 확인, 필요시 Ctrl+C로 서버 중단 후 재시작 |
| 로그인 세션이 끊김 | 디버그 Chrome에서 재로그인 후 이어서 진행 (`resumeFrom` 옵션으로 중간 STEP부터 재시작 가능 — sop.md STEP↔코드 매핑표 참조) |
| 등록 버튼을 눌렀는데 아무 팝업도 안 뜸 | 유령 모달 버그(1장 참조)일 수 있음 — 페이지 새로고침 후 재시도, 반복되면 기록해 둘 것 |

---

## 4. 파일럿 통과 판정 기준

- 위 1단계(새 더미 사건) STEP1~10 완주 성공
- 위 2단계(실사건) 2건 이상, 사람이 손으로 했을 때와 결과 동일
- `needsManualReview` 없이 정상 완료된 비율이 충분히 높다고 판단될 때 (구체적 수치 기준은 운영하며 정할 것)

통과하면 admin 페이지에서 이 흐름을 기본 실행 경로로 전환하고, Claude는 이후 포털 화면이 개편될 때 선택자 재탐지 등 유지보수 용도로만 사용한다.
